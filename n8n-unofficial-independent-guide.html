Part 0

Orientation

What n8n actually is, why it exists, and getting it running on your machine for the first time.

01What is n8n?

n8n (pronounced "n-eight-n," short for "nodemation" — the "8" stands for the eight letters between the n's) is a tool for building automated workflows by connecting things together visually, instead of writing a program from scratch. You drag "nodes" onto a canvas, each node does one job (fetch an email, check a condition, save a row to a spreadsheet), and you draw lines between them to say what happens next. When something triggers the workflow — a new email, a scheduled time, a form submission — n8n runs through the nodes in order and does the work automatically, without you touching it.

Think of it like a flowchart that actually runs. You're not just documenting a process, you're building it.

02History & background

n8n started as an open-source alternative to paid automation tools, built by a small team frustrated with the limits and pricing of existing "no-code" automation platforms. It's released under a "fair-code" license (more on that below), which means the source is visible and self-hosting is free, while the company still funds development through a paid cloud product and enterprise features. This model has let n8n grow a large community of self-hosters alongside its commercial offering.

05Licensing model explained

n8n uses a "fair-code" license (Sustainable Use License), which sits between fully open-source and fully proprietary. In practice: you can self-host n8n for free, including for internal business use, and you can view and modify the source. What you can't do is take n8n and resell it as a competing hosted service. Certain advanced features (like SSO, advanced permissions, and some enterprise governance tools) are reserved for paid Enterprise plans. Always check n8n's current official licensing page for the exact, up-to-date terms, since licensing details can change.

06Installation & setup

There are several ways to get n8n running, from a five-minute local test to a production server:

Quick local test (npx)

npx n8n

This downloads and starts n8n temporarily — nothing is installed permanently. Good for a first look, not for real use.

Docker (recommended for real use)

docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n

This keeps your data in a Docker volume so it survives restarts.

Docker Compose

For anything beyond a quick test, a docker-compose.yml file lets you also run a proper database (Postgres) alongside n8n, set environment variables, and manage restarts cleanly. This is the standard approach for a small production instance.

npm global install

npm install n8n -g
n8n start

Installs n8n directly via Node.js. Useful if you already manage Node versions and want it as a normal CLI tool.

Kubernetes

For larger, team-managed deployments, n8n can run as a Kubernetes deployment, typically paired with queue mode (covered in Part 5) so multiple workers share the load.

One-click platforms (Railway, Render, etc.)

Several hosting platforms offer a one-click n8n template, which handles the Docker setup for you — a middle ground between "npx test" and "manage your own server."

n8n Cloud

n8n's own hosted offering — no installation at all, you sign up and get a ready-to-use instance. Trades self-hosting control for zero maintenance.

Where to click — first login: after starting n8n, open your browser to http://localhost:5678. On first run you'll see a setup screen: enter an email, first name, last name, and password, then click Next / Get Started. This creates your owner account. You'll land on an empty canvas titled "My workflow."

07Your first workflow, click by click

  1. On the empty canvas, click the + button (or the large "Add first step" tile in the middle of the canvas).
  2. A panel opens on the right listing trigger types. Click Trigger manually — this adds a "When clicking 'Execute workflow'" node.
  3. Hover over the small dot on the right edge of that node, click and drag out a line, then release over empty canvas — a search box appears. Type Set and click the Edit Fields (Set) node to drop it and auto-connect it.
  4. Click the new Set node to open its panel on the right. Click Add Field, choose type String, set the name to message and the value to Hello from my first workflow.
  5. Click the Test workflow button (top right of the canvas, or the play icon on the trigger node).
  6. n8n runs the workflow instantly. Click the Set node again — its output panel on the right now shows the data it produced, including your message field.

That's the entire mental model of n8n in six clicks: a trigger starts things, nodes do work, data flows left to right, and you can inspect exactly what happened at every step.

06aNode-vs-code philosophy

A recurring decision in n8n is: drag a node, or drop into the Code node and write JavaScript? General rule of thumb — use a node when one exists for what you need (it's faster, more readable, and easier for someone else to maintain later); reach for Code when the transformation is genuinely custom (complex math, unusual string parsing, logic that would take five chained nodes to express). Overusing Code makes workflows opaque; avoiding it entirely makes some tasks needlessly painful. Most solid workflows are 80% nodes, 20% Code where it earns its place.

06bFair-code vs open-source vs proprietary

It helps to place n8n on a spectrum. Fully open-source (MIT/Apache-style) software can be freely resold and rehosted by anyone, including as a competing paid service. Fully proprietary software hides its source entirely. Fair-code sits between: the source is visible, self-hosting is unrestricted for your own use, but turning the product itself into a competing commercial hosting service is restricted. n8n's specific terms are set out in its official license — treat this section as a mental model, not a substitute for reading the current license text.

Myth"Fair-code" and "open-source" mean the same thing.
RealityThey don't — fair-code adds one specific restriction (no reselling it as a competing hosted service) that plain open-source licenses don't have. Small print, big difference if you're building a business on top of it.

06cSizing a self-hosted instance

  • Light personal use (a handful of workflows, low volume): a small cloud VM (1 vCPU, 1–2GB RAM) with SQLite is usually enough to start.
  • Small team / moderate volume: move to Postgres instead of SQLite for reliability, and give the instance 2–4GB RAM.
  • High volume / many concurrent executions: this is when queue mode (Part 5) becomes worth the setup effort — separating the main n8n process from "worker" processes that actually execute workflows, backed by Redis.
Part 1

Foundations

The mental model underneath every n8n workflow — get this right and everything else clicks faster.

09Core concepts

TermWhat it means
WorkflowA saved collection of connected nodes that together automate a task.
NodeA single step that performs one action (fetch data, transform it, send it somewhere).
TriggerThe special first node that starts a workflow (a webhook call, a schedule, a manual click).
ActionAny node after the trigger that does something with the data.
ConnectionThe line between two nodes — defines the order and the flow of data.
ExecutionOne complete run of a workflow from trigger to finish, logged with its data.
CredentialsSecurely stored login details / API keys a node uses to connect to a service.
Data flowThe way information passes from node to node, transformed at each step.

10n8n architecture

  1. Trigger — something starts the workflow (webhook, schedule, manual run, app event).
  2. Workflow — the saved sequence of nodes that will run.
  3. Nodes — each one fetches, filters, transforms, or calls out to an API.
  4. Transform data — data gets cleaned, mapped, or reshaped as needed.
  5. Decision — conditional nodes (IF/Switch) route data down different paths.
  6. API calls / integrations — the workflow talks to external apps, databases, or services.
  7. Output — the final result is delivered — an email sent, a row saved, a message posted.

Workflows can also loop back — repeating steps for each item in a list, or waiting and retrying — rather than running strictly in one straight line.

11Types of nodes

Trigger nodes

Start a workflow: Schedule/Cron, Webhook, Email Trigger, Chat Trigger, Manual Trigger, Form Trigger.

Core nodes

Control and transform data: Set, IF, Switch, Merge, Wait, Loop Over Items, Code, Function.

App nodes

Connect to 400+ specific apps: Gmail, Google Sheets, Slack, Notion, Airtable, Google Drive, Discord, GitHub, and many more.

AI nodes

AI Agent, Chat Model, Embeddings, Vector Store, Memory, Retriever.

Utility nodes

HTTP Request, Set Binary Data, NoOp, Error Trigger — general-purpose helpers that don't belong to one specific app.

13The n8n data structure

Every node passes data as a list of "items." Each item is an object with a json property (the structured data) and, optionally, a binary property (file data). This is why an expression like {{ $json.name }} works everywhere — every node's output is standardized into this same item shape, regardless of which app it came from.

n8n also tracks pairedItem information behind the scenes — a link from each output item back to the input item(s) it came from. This is what lets n8n correctly map data back through Merge and other multi-input nodes, and it's the usual culprit when you see "can't find pairing" errors after heavy custom transformation in a Code node — the fix is usually to preserve or manually set pairedItem in your returned items.

14Execution modes

Manual

You click "Test workflow" yourself. Best for building and debugging.

Triggered

Runs automatically whenever its trigger condition fires — time-based, event-based, or webhook-based.

Webhook

A specific case of triggered mode where an external system calls your workflow's URL directly, in real time.

Queue mode

For scaling: a "main" process receives triggers and hands executions off to separate "worker" processes via a Redis-backed queue, so heavy workflows don't block the whole instance. Covered in depth in Part 5.

Polling vs event-based: some triggers (like many app triggers) work by polling — n8n checks the app every so often ("any new rows since last check?"). Others, like webhooks, are event-based — the app pushes data to n8n the instant something happens, with no delay and no wasted checks. Event-based is more efficient and immediate where it's available.

09aSticky Notes & documenting your workflow

The Sticky Note node isn't a functional step — it's a colored text box you drop onto the canvas to leave notes for your future self or teammates ("this branch handles refunds," "TODO: add retry here"). Add one via the + panel, search Sticky Note. Cheap habit, huge payoff once a workflow has more than five or six nodes.

09bPin Data

Pin Data freezes a node's current output so that re-running the workflow doesn't re-fetch it — useful when you're iterating on nodes downstream of a slow or rate-limited API call. Where to click: run the workflow once, then click the node whose output you want to freeze, click the pin icon in its output panel. A pin icon appears on the node; unpin the same way when you're done testing.

09cPartial execution & "test step"

You don't have to run an entire workflow to check one node. Click any node, then click Test step (or the small play icon on the node itself) to run just that node using whatever data is currently available upstream. This is the fastest debugging loop in n8n — build one node, test it, move to the next.

10aActivation vs deactivation

The toggle in the top-right of the canvas switches a workflow between Active and Inactive. Inactive workflows can still be run manually, but their triggers (webhooks, schedules, app polling) are switched off — no live traffic reaches them. Activating a workflow registers its webhook URL and starts its schedules for real; this is the step people most often forget after building something that "works" in testing but never fires on its own.

10bStatic data & node versions

Workflow-level static data (accessed via $getWorkflowStaticData in a Code node) lets a workflow remember a small piece of state between separate executions — for example, "the ID of the last row I processed," so a polling workflow doesn't reprocess old data. Separately, n8n nodes carry an internal version number; when n8n upgrades a node's behavior, older workflows keep running the version they were built with unless you explicitly update the node, which is why upgrading n8n rarely breaks existing workflows outright.

Quick check: what starts every workflow in n8n?
Correct answer: a Trigger node. Manual, Webhook, Schedule and the rest are all the entry point — nothing else runs until one of them fires.

Core Skills

The handful of nodes and concepts that show up in almost every workflow you'll ever build.

17Control flow nodes

Beyond the core seven, n8n has a fuller family of flow-control nodes: Stop and Error (deliberately fail a workflow with a custom message), Continue on Fail (a per-node setting, found in the node's "Settings" tab, that lets the workflow keep going even if that node errors), and NoOp (does nothing — useful as a placeholder while sketching a workflow's shape before filling in the real logic).

Where to click — Continue on Fail: click any node → the small "..." or settings icon on the node panel → toggle Continue On Fail. The node's error output can then be wired to a separate handling path instead of stopping the whole run.

21Working with JSON

Because everything in n8n is JSON under the hood, reading nested data is just chaining dots and brackets: $json.user.address.city for a nested object, $json.items[0].name for the first element of an array. When a field name has spaces or special characters, use bracket syntax instead: $json["Full Name"]. The Edit Fields (Set) node's mapping mode lets you drag a field from the input panel directly onto an output field, which writes the correct expression for you automatically — a good way to learn the syntax by watching what n8n generates.

22Dates & times

n8n uses the Luxon library for date handling under expressions and Code nodes. $now gives the current moment, $today the current date. Common patterns: $now.toFormat('yyyy-MM-dd') to format a date, $now.plus({days:7}) to add time, and $now.setZone('Asia/Kolkata') to convert timezones. Always be explicit about timezones in scheduled workflows — a Cron trigger's time is based on the instance's configured timezone, which is easy to get wrong when your server and your users are in different regions.

23Regular expressions

Inside a Code node, or in the IF node's "Regex" operator, standard JavaScript regular expressions work as expected — e.g. matching an email pattern before accepting form input, or extracting a specific pattern (like an order number) out of a longer text string with .match(/ORD-\d+/).

24Pagination patterns

Many APIs return data one "page" at a time. The common n8n pattern is: an HTTP Request node inside a loop, where each iteration reads a "next page" token or offset from the previous response and feeds it into the next request's query parameters, stopping when the API signals there's no more data (an empty result, or a missing "next" token). n8n's HTTP Request node also has a built-in pagination option in its parameters for APIs that follow standard patterns, which can remove the need to build the loop manually.

25Sub-workflows

The Execute Workflow node lets one workflow call another as a reusable building block — passing data in, getting a result back — the same way a function call works in programming. This is how you avoid duplicating the same 10-node sequence across five different workflows: build it once, call it from anywhere.

16aSplit Out vs Item Lists

These overlap in purpose and cause confusion. Split Out takes one item containing an array field and turns each array element into its own separate item — useful right after an API call that returns a list nested inside one response object. Item Lists (now largely folded into other nodes in newer versions) historically handled broader array operations like removing duplicates or combining lists. If you're on a recent n8n version, check the current node picker — some of this functionality has been consolidated, so search by task ("split," "aggregate") rather than by an exact remembered node name.

16bAggregate, in depth

Aggregate does the reverse of Split Out — many items become one, grouped as needed. Typical use: after looping through 50 rows and doing something to each, Aggregate collapses them back into a single item containing an array, ready to be written as one batch instead of 50 separate write operations.

16cCompare Datasets

The Compare Datasets node takes two inputs and tells you what's new, what's removed, and what changed between them — handy for sync workflows (e.g., "what changed in this spreadsheet since last time I checked").

16dRename Keys / Edit Fields naming history

The node currently called Edit Fields (Set) was previously just called Set, and some older tutorials/templates still refer to it that way — they're the same node. If you import an older workflow and see a node simply labeled "Set," that's this node under its earlier name.

16eConvert to File / Extract From File

Convert to File turns JSON data into a downloadable file (CSV, JSON, or others) as binary output — useful before emailing a report or uploading to storage. Extract From File does the reverse: reads an uploaded/incoming file (CSV, spreadsheet, PDF text) and turns it back into structured JSON items you can work with.

19aArrays at scale (map/filter/reduce in Code)

Inside a Code node, you have the full power of JavaScript array methods on $input.all(): .map() to transform every item, .filter() to keep only some, .reduce() to collapse an array into a single summary value (a total, a count, a grouped object). This is the escape hatch for logic that would need an unreasonable number of chained nodes to express visually.

// Example: sum a field across all items in a Code node
const total = items.reduce((sum, item) => sum + item.json.amount, 0);
return [{ json: { total } }];

19bItem-pairing gotchas

The most common confusing error in n8n is data seeming to "disappear" or nodes complaining they can't match items after a Merge or a heavy Code transformation. This almost always comes back to pairedItem (see §13) getting lost — usually because a Code node built brand-new output items without preserving a link back to their source. Fix: when returning items from Code, keep the original item object as a base and only edit its .json, rather than constructing a completely new item from scratch.

Quick check: which core node do you reach for when nothing visual quite covers what you need?
Correct answer: Code — your escape hatch for custom JavaScript logic when a chain of visual nodes would be slower or messier (see §16a).
Part 3

Connecting to the World

Webhooks, APIs, auth, databases, cloud apps and files — how n8n talks to everything else.

26Webhooks

A webhook is a URL that n8n generates for you; when an external system sends an HTTP request to that URL, your workflow runs instantly with whatever data was sent — the opposite of n8n having to go ask for data.

Where to click: add a Webhook node → its panel shows a Test URL and, once the workflow is activated, a separate Production URL — copy whichever you need with the copy icon next to it. Set the HTTP Method (usually POST) in the same panel.

Security: for anything beyond a private test, don't leave a webhook wide open. Options include: requiring a header/basic-auth credential (set directly on the Webhook node's Authentication field), validating an HMAC signature the sender includes (checked in a Code or IF node against a shared secret), and, on self-hosted instances, restricting which IPs can reach the endpoint at the network/firewall level.

Where to click — OAuth2 setup: Credentials → New → pick the app's OAuth2 credential type → fill in Client ID/Secret from that app's developer console → click Connect my account → a consent screen opens in a popup → approve it → n8n stores and auto-refreshes the token from then on.

The fix is almost always to reconnect the credential from scratch via the same "Connect my account" flow, rather than trying to debug the token.

32GraphQL in n8n

There's no dedicated GraphQL node — instead, you use the HTTP Request node in POST mode, set the body to your GraphQL query/mutation as a JSON payload (typically a query field and a variables object), and point it at the API's GraphQL endpoint. Authentication works the same as any other HTTP Request call.

33Rate limiting & throttling

When calling an API that limits how many requests you can make per minute, the common patterns are: a Wait node inserted inside a loop to space out calls, the HTTP Request node's built-in retry-with-backoff (Settings tab) for handling occasional 429 "too many requests" responses gracefully, and Split In Batches to process large datasets in smaller, paced chunks rather than firing hundreds of parallel requests at once.

26aMultipart/form-data uploads

To upload a file to an API that expects multipart/form-data (common for file-upload endpoints), set the HTTP Request node's Body Content Type to "Form-Data," then add a parameter of type "n8n Binary File" pointing at the binary property on your incoming item (usually named data). This tells n8n to encode the request the way the receiving server expects, instead of sending raw JSON.

26bCustom API wrapper pattern

For an undocumented or awkward internal API, a useful pattern is to build one small "connector" sub-workflow (see §25) that handles auth, base URL, and error normalization for that API once, then have every other workflow call that sub-workflow instead of repeating the HTTP Request setup everywhere. Change the API's auth once, in one place, instead of hunting through every workflow that touches it.

26cWhere n8n doesn't fit: WebSockets / long-polling

n8n is built around discrete request/response and event-triggered execution — it isn't designed to hold open a persistent two-way WebSocket connection indefinitely inside a single node. For genuinely real-time, bidirectional streaming needs, a small dedicated service that receives the WebSocket stream and then calls an n8n webhook per event is the more realistic pattern than trying to force it entirely inside n8n.

26dNative Form Trigger & Form node

n8n can host its own simple web forms without needing Typeform or Google Forms — the Form Trigger node generates a hosted form URL with fields you define directly in the node, and the newer Form node (used mid-workflow) can show additional form steps, enabling basic multi-step forms natively. Good for quick internal intake forms where you don't want a separate tool in the stack.

26eRespond to Webhook node

By default, a Webhook node waits until the whole workflow finishes before sending a response back to the caller. The Respond to Webhook node lets you send a custom status code, headers, and body back explicitly — including sending an immediate "received, thanks" response while the rest of the workflow keeps processing in the background (set the Webhook node's "Respond" option to "Using Respond to Webhook Node" and place that node early in the flow).

26fChat Trigger & built-in Chat UI

The Chat Trigger node comes with a ready-made, embeddable chat window — useful for testing or lightly deploying a chatbot workflow (Part 4) without building a separate frontend. Add the node, and n8n gives you a shareable chat link/widget that sends each message into your workflow as a trigger.

Somewhere, right now, an unsecured webhook is quietly making someone's Monday a lot more interesting than planned. Lock yours down (§26) before it's your turn.

35Building a RAG pipeline, step by step

  1. Load your source documents (files, a Notion database, scraped pages) with the relevant file/app node.
  2. Use a Text Splitter (in the AI nodes panel) to break long documents into manageable chunks.
  3. Pass each chunk through an Embeddings node to generate its vector representation.
  4. Store the chunks and their vectors in a Vector Store node (e.g. Pinecone, or a self-hosted option).
  5. At query time, embed the incoming question the same way, and use a Retriever to pull the most relevant stored chunks.
  6. Feed those chunks plus the original question into a Chat Model node as context, so the model answers grounded in your actual data instead of guessing.

36Building a chatbot, step by step

  1. Add a Chat Trigger node — this gives you a ready chat UI and starts the workflow on each incoming message.
  2. Connect it to an AI Agent node (or a plain Chat Model for simpler bots).
  3. Add a Memory node so the bot remembers earlier turns in the same conversation.
  4. Add any tools the bot needs (looking up an order, checking a knowledge base) as Tool connections on the Agent.
  5. Test in the built-in chat panel, then activate the workflow to make it live.

37How the AI Agent picks and calls tools

An Agent node is given a goal (the incoming message/instruction) and a list of tools it's allowed to use — each tool described in plain language ("looks up a customer's order status," "sends a Slack message"). The underlying LLM reasons about which tool, if any, would help answer the request, calls it (n8n actually executes that connected node), reads the result, and decides whether it needs another tool call or can now respond. This loop can repeat several times before the Agent gives its final answer — which is why Agent workflows can feel slower than a single Chat Model call, and why giving an Agent too many overlapping tools tends to make its choices less reliable.

MythAn AI Agent always knows the right tool to use.
RealityIt's a confident guesser with a toolbox — hand it too many overlapping tools and its choices get noticeably less reliable, not more capable.

38Prompt engineering basics for n8n AI nodes

  • Be specific about the output format you want ("respond only with valid JSON matching this shape...") if a downstream node needs to parse the result.
  • Give the model the minimum context it actually needs — bloated prompts cost more and can dilute relevance.
  • For Agents, write tool descriptions the way you'd explain the tool to a new colleague, not just a technical function name — clearer descriptions produce better tool selection.
  • Test prompts directly in the node before wiring the whole workflow around them; expression previews let you see exactly what's being sent.

39Cost control for AI nodes

  • Set explicit token/length limits where the node allows it, rather than letting responses run unbounded.
  • Cache repeated lookups (e.g. store an embedding once instead of re-generating it every run) using a database or the Vector Store itself.
  • Choose the smallest model that reliably does the job for a given step — not every task needs your most expensive model.
  • Log token usage where the provider's node exposes it, so cost creep is visible before it becomes a surprise.

34aStructured output parsing from LLMs

When a downstream node needs to act on an LLM's answer programmatically (not just display it), ask the model for JSON in a specific shape, and use n8n's Output Parser option on the Chat Model / Agent node (or a Code node fallback) to validate and parse it before anything downstream trusts it. Never wire a raw, unvalidated LLM string straight into an action like "send this email" or "run this database update" — validate the shape and sanity-check the content first.

34bMulti-agent orchestration

For complex tasks, one workflow can coordinate several specialized Agents — for example, a "router" Agent that classifies the incoming request and hands it to a "billing" Agent or a "technical support" Agent sub-workflow, each with its own narrow toolset. This tends to produce more reliable results than one Agent with a huge, overlapping list of tools trying to do everything.

34cLocal/open-source LLMs (Ollama) vs hosted APIs

The Ollama node lets n8n talk to locally-run open-source models instead of a hosted provider's API — useful for cost control, data privacy (nothing leaves your server), or offline use. Trade-off: local models typically need meaningful GPU/CPU resources on the host machine and may lag behind the largest hosted models in raw capability, so the right choice depends on whether privacy/cost or peak capability matters more for a given workflow.

38aGuardrails before real-world actions

Any time an AI node's output is about to trigger something consequential — sending an email, writing to a database, making a payment call — add an explicit validation step between the AI and the action: a Code or IF node checking the output is well-formed, within expected bounds, and doesn't contain anything obviously wrong, before the action node runs. This single habit prevents the most common category of "AI automation gone wrong" stories.

45Scaling n8n (queue mode)

In queue mode, a "main" n8n process still handles the editor UI and receives triggers, but instead of executing workflows itself it pushes each execution onto a Redis-backed queue. Separate "worker" processes (which you can run several of, on the same or different machines) pull jobs from that queue and actually run them. This lets you scale execution capacity horizontally by adding more workers, independent of the main process — the standard approach once a single instance can't keep up with concurrent load.

46Version control for workflows

A workflow can be exported as JSON (from the workflow menu, "Download") and committed to a normal git repository, giving you real diffs, history, and rollback outside of n8n itself. Some teams script this export/import as part of a proper CI pipeline, so workflow changes go through the same review process as code.

47Security hardening checklist

  • Store all secrets in Credentials or Environment Variables — never hardcoded in a node's fields or expressions.
  • Protect webhook endpoints with authentication or signature validation (§26).
  • Limit which network addresses can reach a self-hosted instance's admin UI.
  • Use least-privilege database users and API keys wherever a service supports scoped permissions.
  • On Enterprise plans, use role-based access control to limit who can view/edit which workflows and credentials.
  • Rotate credentials periodically, and immediately after any team member with access leaves.

40aMulti-environment strategy

A durable pattern for teams: separate instances (or at minimum separate credential sets and environment variables) for development, staging, and production, with workflows promoted between them deliberately — export/import or git-based (§46) — rather than editing "the one instance" directly for both testing and live traffic.

40bTeam collaboration & permissions

On team/enterprise setups, workflows and credentials can be shared across specific users or groups rather than being all-or-nothing. Role-based access control (who can view vs edit vs manage credentials) is one of the features reserved for paid Enterprise tiers (§5) — self-hosted community use typically has simpler, coarser permission handling.

40cBackup & disaster recovery

For self-hosted instances, back up both the underlying database (Postgres/SQLite holding workflows, credentials, execution history) and your environment configuration, on a real schedule — not just an occasional manual export. Test the restore process at least once; a backup you've never restored from is an assumption, not a plan.

42aBlue-green / canary rollout for workflow changes

For a business-critical workflow, avoid editing the live version directly. Duplicate it, make and test changes on the copy, then switch traffic over (repoint the webhook, or swap which workflow is activated) once you're confident — giving you an instant rollback path if something's wrong, the same discipline used for deploying application code.

42bRotating secrets without downtime

Where a service supports it, create the new credential/key alongside the old one, update the workflow's credential reference, confirm it works, and only then revoke the old key — rather than revoking first and discovering the break in production.

Part 6

Extending n8n

What to do when a built-in node isn't enough, and how to manage n8n itself programmatically.

49Community nodes

Beyond the built-in node library, the community publishes additional nodes (as npm packages) for niche apps and services.

Where to click: Settings → Community Nodes → Install → type the npm package name → confirm the install dialog. n8n will restart the relevant part of the instance and the new node appears in your node search.

Only install community nodes from sources you trust — since a community node can run arbitrary code inside your instance, treat installing one with the same caution you'd apply to installing any third-party package.

50Building a custom node

When even a community node doesn't exist for what you need, n8n supports building your own: scaffold a new node project (n8n provides a starter template), define its parameters and execution logic in TypeScript, test it locally against your own instance, then optionally publish it to npm and submit it for community verification. This is a meaningfully bigger undertaking than building a workflow — reach for it only when a Code node genuinely can't cover the need and you expect to reuse the integration repeatedly.

51n8n's own API

n8n exposes a REST API for managing the instance itself, separate from any workflow you build inside it — letting you programmatically list/create/update workflows, trigger and inspect executions, and manage credentials and users. This is how larger organizations manage n8n at scale — deploying workflow changes via CI/CD, or building an internal admin tool on top of it — rather than only ever clicking through the UI.

52n8n CLI basics

The n8n command line tool (available wherever you've installed n8n via npm) supports operations like starting the instance, exporting/importing workflows and credentials in bulk, and running database migrations — useful for scripting instance setup or migrating between environments without doing it by hand through the UI.

53Templates & the community library

n8n maintains a public library of pre-built workflow templates covering common use cases, which you can import as a starting point and adapt rather than building from a blank canvas every time. Importing a template is the fastest way to see a well-structured example of patterns covered elsewhere in this guide (error handling, sub-workflows, AI agents) in a real, working context.

49aLocal webhook testing & tunneling

While developing a webhook-triggered workflow on a machine that isn't publicly reachable (your laptop, a local Docker instance), a tunneling tool exposes a temporary public URL that forwards to your local n8n instance, so external services can actually reach your Test URL during development. Once you deploy to a properly hosted instance, the tunnel is no longer needed — it's a development convenience, not a production setup.

49bCustom node development lifecycle

  1. Scaffold the project using n8n's node starter template.
  2. Define the node's parameters (what shows in its right-panel UI) and its execution function (what it actually does with input data).
  3. Run it against a local n8n instance in development mode to test it live.
  4. Package and publish it to npm under the expected naming convention for n8n community nodes.
  5. Optionally submit it for n8n's community verification process, which adds a level of trust signal for other users installing it.

49cn8n embed / white-labeling

For teams building automation into their own product, n8n offers ways to embed its workflow-building experience or run it under your own branding rather than exposing the standalone n8n UI directly to your end customers — a path worth knowing about if you're building a SaaS product with automation as a feature, rather than using n8n purely as an internal tool.

Part 6.5

Design Patterns

Shapes that show up again and again once you've built enough workflows — and the shapes to avoid.

·Fan-out / fan-in

One item triggers several parallel branches (fan-out — e.g. notify Slack, log to a database, and send an email all at once), which later reconverge through a Merge node (fan-in) before a final shared step. Good for independent actions that don't depend on each other's results.

·Batch processing

Split In Batches breaks a large dataset into fixed-size chunks and loops through them, so you're never holding an unreasonable amount of data in memory at once, and a failure partway through only affects the current batch rather than the whole dataset.

·Polling-vs-webhook hybrid

When an app only offers polling but you want faster reaction times, a tight polling schedule (e.g. every minute) combined with a static-data "last seen" marker (§10b) approximates near-real-time behavior without needing true webhook support from that app.

·Retry-with-backoff

Instead of retrying a failed call immediately (and possibly hitting the same transient issue again instantly), wait progressively longer between attempts — a Wait node with an increasing duration, or the HTTP Request node's built-in retry settings, before giving up and routing to error handling.

·Idempotency keys

For workflows that might run twice for the same event (a webhook retried by the sender, a manual re-run), include a unique identifier from the source event and check whether you've already processed it (e.g. against a database) before taking action again — prevents duplicate emails, duplicate charges, duplicate records.

·Dead-letter handling

Rather than letting a permanently failing item vanish, route items that exhaust their retries into a dedicated "failed items" log (a database table, a spreadsheet) for manual review later — so persistent failures are visible and actionable instead of silently lost.

·Anti-patterns to avoid

  • Monolithic workflows — one 80-node workflow doing five unrelated jobs is hard to test, hard to debug, and risky to edit.
  • Hardcoded secrets — any API key or password typed directly into a node's field instead of a Credential or Environment Variable.
  • Missing error paths — a workflow with no Error Workflow and no Continue On Fail anywhere is one bad API response away from silently going dark.
  • Unbounded loops — a Loop Over Items with no limit and no failure exit can run far longer, and cost far more (especially with AI nodes), than intended.

58aReading the canvas

A green dot on a node's edge is a standard data output/input connector; dragging between two of them creates a connection. A red output on some nodes represents an explicit error path (used with Continue On Fail) — wiring something to it lets you handle failures for that specific node separately from its normal success path. Dotted vs solid connection lines generally distinguish a configured-but-not-yet-run connection from one that has live execution data flowing through it in the current view.
